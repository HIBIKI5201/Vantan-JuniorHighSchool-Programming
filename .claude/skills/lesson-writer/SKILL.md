# 授業資料(レッスン)を書く

このリポジトリはバンタン中等部のScratch授業資料を公開する静的サイト。
1回の授業 = `src/content/lessons/<courseSlug>/<NN>.md` の1ファイル。

書き方の詳しいルールは [docs/content-notation.md](../../../docs/content-notation.md) にある。
このスキルは「実際に1回分を書き上げるまでの手順」をまとめたもの。

**本文のトーンは必ず [docs/writing-voice.md](../../../docs/writing-voice.md) に従うこと。**
先生の言い回し(「〜しましょう」「なので」「！！」の使い方、一人称は「先生」など)を
実際の既存資料から数えて抜き出したもの。書き上げたら読み返して、外れていないか確かめる。

用語ページ(Scratch wiki)を足す時は `wiki-term-writer` スキルの方を使う。

## 手順

### 1. その回に何を書くかを決める

**必ず先に読む:**

- `src/content/lessons/<courseSlug>/00.md` — その期のゲーム企画。作るゲームの仕様が全部書いてある
- 直前の回(`<NN-1>.md`) — 変数名・ブロック定義名・どこまで作ったか

企画に書かれていて**まだ作っていない機能**を探し、そこから次の回の題材を決める。
前の回の「終わり」に「次回は◯◯」と書いてあれば、それを優先する。

授業1回はだいたい **手順の見出し(`###`)が8〜12個**。それ以上になるなら回を分ける。

新しく書いた回は、仕上がるまで `status: draft` のままにしておくこと。

### 2. 雛形を作る

```bash
npm run new-lesson -- <courseSlug> <回数> "<タイトル>" [手順の数]
```

`src/content/lessons/<courseSlug>/<NN>.md` と、スクショ置き場の
`public/lessons/<courseSlug>/<NN>/` が作られる。

タイトルは「◯◯を作ろう」の形に揃える(例: `#4 タイトルとリザルトを作ろう`)。

### 3. 本文を書く

構成は既存の回に揃える。

```markdown
# #4 タイトルとリザルトを作ろう

作成日時: 2026年8月17日
授業日: （授業日を入れる）

# 目標
- ゴールを3つくらい箇条書き

# 見本
先生のプロジェクトです！
完成品として参考にしてください。

（先生のプロジェクトURLを入れる）

## 今日のひとことを書こう！

https://forms.gle/2pMUF3bXP67FiUdA8

# やってみよう
## 大きなまとまり
### 手順の見出し
（スクショ → aside → 番号リスト）

# 終わり
## エクストラ課題
### 追加でやってみること
```

### 4. 確認する

```bash
npm run check
```

エラーが0になるまで直す。そのあと `npm run build` が通ることも確認する。

### 5. 授業のあと: スクショを取り込む

授業中に撮ったスクリーンショットを `public/lessons/<courseSlug>/<NN>/` に放り込んでから:

```bash
npm run shots -- <courseSlug> <回数> --dry-run   # どう並ぶか見る
npm run shots -- <courseSlug> <回数>             # 実行
```

「スクリーンショット 2026-08-21 005102.png」のような名前を、撮った順に
`image-0.png` / `image-1.png` / … へ自動で並べ替える。
並び順が違ったら、そのフォルダの中でファイル名を入れ替えれば直る。

スクショと授業日と見本URLが埋まったら `status` を `complete` にして公開する。

## 書き方のルール

### 見出しの段数

このリポジトリには2つの流儀があり、**1つのコースの中では必ず揃える**。
2026年7月〜のコース(`kinyo-2026-7-9` / `suiyo-2026-7-9`)は次の形:

| 段 | 使い方 | 例 |
| :--- | :--- | :--- |
| `#` | ページタイトル と 大セクション | `# やってみよう` `# 終わり` |
| `##` | 中くらいのまとまり | `## 敵に体力をつけよう` |
| `###` | 手順ひとつ | `### 敵の体力の変数を作る` |

### 手順1つの型

`###` の下は必ず **スクショ → aside → 番号リスト** の順。役割分担が決まっている。

```markdown
### 敵の体力の変数を作る

![image.png](/lessons/kinyo-2026-7-9/03/image-0.png)

<aside>
💡

今の敵は一回当たったら消えてしまいますね。
これだと強く引っ張っても弱く引っ張っても同じなので、引っ張る意味がありません。

名前は”EnemyHealth”にします。Enemyは「敵」、Healthは「体力」なので、「敵の体力」という意味ですね。

</aside>

1. 変数を作るボタンを押す
2. 名前を”EnemyHealth”にする
3. “このスプライトのみ”にする
```

- **aside の中には手順を書かない。** asideは「なぜ・何をするか」、外の番号リストが「具体的な操作」
- ブロックの置き場所は**すぐ隣のブロック名を出して**書く。「下に」だけだと生徒が迷う
  - ✕「ダメージのブロックの下に入れます」
  - ○「”もし EnemyHealth < 1 なら”ブロックの**下**に繋げます」

### asideのトーン(中学生向け)

- です・ます調で語りかける(「〜しましょう」「〜ですね」)
- **新しい変数名・ブロック定義名は英単語の意味を必ず添える**
  例:「名前は”MoveSpeed”にします。意味はそのまま「移動のスピード」ですね。」
- 「なぜこの操作が必要か」を先に一言 → そのあと何をするか
- 「こうすると〜になります」と結果を書く
- **わざと失敗させてから直す構成は効果的**。「ここで一回遊んでみましょう。……一瞬で消えてしまいませんか？」
  のように、バグを体験させてから原因と直し方を説明すると理解が深まる

### スクリーンショット

先生があとから撮って貼るので、**本文には最初から画像リンクを書いておく**。

```markdown
![image.png](/lessons/<courseSlug>/<NN>/image-0.png)
```

- ファイル名は `image-0.png` → `image-1.png` → `image-2.png` … の順。**番号なしは使わない**
- パスは `/lessons/...` から書く(GitHub Pagesのbaseは自動で付くので書かない)
- **実体が無い間はビルド時に「スクリーンショット準備中」の枠に自動で差し替わる**ので、
  壊れた画像にはならない。`public/lessons/<courseSlug>/<NN>/` に置けば次のビルドから出る
- **書きかけの回は `status: draft` にする。** 公開サイトには出ず、`npm run dev` でだけ見える
  (生徒に未完成の資料を見せないため)。スクショと授業日と見本URLが埋まったら
  `complete`(画像がまだなら `partial`)に変えて公開する

### 用語リンク(Scratch wiki)

**基本は何も書かなくてよい。**
asideの説明文に用語が出てくれば、その手順の後ろに用語カードが自動で挿入される
(`remarkAutoWikiTerms`。1つのasideから最大2件、同じ用語は1ページ1回まで)。

つまり **asideの中で用語をきちんと言葉にして書く**ことが、そのままリンクになる。

自動では拾えない場所(asideの無い「覚えること」など)だけ、手で書く。

```markdown
[クローン](wiki:クローン)
```

- `wiki:用語名` と書けばビルド時に実際のページ番号に解決される。**番号を直接書かない**
- リンクの文字は用語ページの正式タイトルに自動で揃うので、表記ゆれを気にしなくてよい
- 「クローンとは：」のような前置きは**書かない**(専用の用語カードとして表示される)
- 読みガナ付きのページは括弧を含めても外しても引ける
  (`wiki:初期化（しょきか）` でも `wiki:初期化` でもよい)
- 対応するページが無いと `npm run check` がエラーにする

**用語ページが足りない時は先にwikiに追加する。**
`src/content/lessons/scratch-wiki/<NN>.md` に、番号の続きで作る。
既存の用語: 変数 / 条件 / 初期化 / メッセージ / インゲーム・アウトゲーム / スプライト /
コスチューム / 座標 / 乱数 / クローン / ブロック定義 / 引数 / 当たり判定 / フレーム / フラグ

### 見本とフォームのリンク

URLを裸のまま1行書く。リンクの文字は remark が自動で
「先生の見本プロジェクト」「今日のひとことフォーム」に置き換えるので、
`[見本](url)` のように自分で書かなくてよい。

先生のScratchプロジェクトURLはこちらでは分からないので、
`（先生のプロジェクトURLを入れる）` と書いて残しておく。

### エクストラ課題

早く終わった生徒向け。2〜3個。次の型が使いやすい。

- **数値の調整**(作った変数の値を色々変えてみる)
- **数を増やす**(敵の種類、ステージなど)
- **考えさせる**(答えを書かずに「どう計算すればいいか考えてみてください」で終える)

## Scratchの内容で気を付けること

- 変数のスコープを毎回明示する。敵1体ずつ別々に持つ値は必ず **”このスプライトのみ”**、
  スプライトをまたいで読む値は **”すべてのスプライト用”**
- `ずっと` や `〜まで繰り返す` の中身は1秒に約30回動く。
  「触れている間ずっと」処理すると一瞬で終わるので、`〜まで待つ` で離れるのを待つ
- 見た目を変える演出(明るさ・幽霊・大きさ)を入れたら、**必ず初期化で元に戻す**手順も書く
- クローンを使ったらオリジナルは `隠す`、クローン側で `表示する`
