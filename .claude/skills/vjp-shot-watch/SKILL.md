# FireShotの待ち受けと取り込み

先生が撮ったスクショを、資料の画像枠に入れ続けるためのループ。
**機械でできること(待つ・新着の検出・重複と白画像の判定・ダイアログの判定・空き枠の一覧・コピーと赤枠)は
すべて `scripts/shot-watch.mjs` がやる。** Claudeがやるのは、画像を見て
「どの手順の画像か」を決めることと、赤枠の位置を決めることだけ。

取り込みの基本ルール(撮り直しの扱い、1手順に複数枚、赤枠を付ける/付けない)は
[vjp-lesson-writer](../vjp-lesson-writer/SKILL.md) の「5. 授業のあと: スクショを取り込む」「5b. 赤枠」に従う。

## 使うコマンド

```bash
node scripts/shot-watch.mjs seen                       # 最初の1回: 今あるスクショを全部「取り込み済み」にする
node scripts/shot-watch.mjs slots <courseSlug> <回数>   # 画像がまだ無い枠の一覧(番号 と 手順の見出し)
node scripts/shot-watch.mjs wait                       # 新しい画像が出るまで待つ(この間は出力なし)
node scripts/shot-watch.mjs place <画像> <courseSlug> <回数> <番号> [x,y,w,h ...]   # コピー + 赤枠
node scripts/shot-watch.mjs ack <画像> [<画像> ...]     # 取り込んだ画像を「取り込み済み」にする
```

`npm run shotwatch -- <サブコマンド> ...` でも同じ。

## 手順

### 0. 準備(最初の1回だけ)

1. 対象の回を確認する: `slots` で空き枠を出す。枠の並び(=撮ってもらう順番)を先生に伝える
2. **`seen` を動かす前に、今回の分がすでにフォルダにあるかを必ず確認する。**
   `seen` は「今あるスクショ全部」を取り込み済みにするので、撮り済みの今回の分まで消えてしまう。
   確認は、最新の数枚のファイル名(`FireShot Capture NNN - <プロジェクト名>`)と撮った時刻を見る。

   ```bash
   ls -l --time-style=+%m-%d_%H:%M ~/Downloads/FireShot | tail -8
   ```

   - 今回のプロジェクトの画像がすでにある → **`seen` は使わない。** そのまま `wait` に進む(あるものがすぐ出てくる)。
     古い画像が大量に混ざる時は、今回より前の分だけを取り込み済みにする(`ack` に古いファイルを渡す)
   - 今回の分がまだ無い → `seen` で全部取り込み済みにしてから `wait`
   - 迷ったら先生に「もう撮ってある分はありますか」と聞く

### 1. 待つ(トークンを使わない)

`wait` を **Bashの `run_in_background: true`** で動かす。

```bash
node scripts/shot-watch.mjs wait --timeout 60
```

- 新しい画像が出るまでスクリプトが黙って待つ。**Claudeはこの間なにもしない・確認もしない**
  (ポーリングや `sleep` はしない。終わると自動で呼び戻される)
- 60分たっても新しい画像が無いと `{"status":"idle"}` で終わる。その時は先生の作業が続いていそうなら
  もう一度 `wait` を動かす(続きを待つだけなので、何も言わなくてよい)
- 書き込み途中のファイルは、大きさが変わらなくなってから出てくる
- **最後の新着から20秒(`--quiet` で変えられる)静かになるまで待ってから、まとめて1回で返す。**
  先生が1枚ずつ撮っている間に何度も呼び戻されないため

### 2. 新着を確認する

`wait` の出力(JSON)に、新しい画像ごとに次が入っている。

| 項目 | 意味 |
| :--- | :--- |
| `name` / `time` | ファイル名と撮った時刻 |
| `title` | 撮った時のタブ名(例: `Shooting #4`)。**別のプロジェクトの画像が混ざっていないかの確認に使う** |
| `kind` | `normal`: Scratchの通常画面 / `dialog`: 変数・メッセージの作成ダイアログ / `other`: それ以外 |
| `blank` | 白一色に近い(何も写っていない)。`true` の画像は使わない |
| `dup` | これまでに取り込んだ画像・同じ回に出た画像と**中身が同じ**。`true` は撮り直しの重複なので使わない |

**機械で決められる分はここで決める。**

- `dup: true` `blank: true` は、画像を開かずに捨てる(先生への報告には入れる)
- `kind: dialog` の画像は、赤枠を付けない
- `title` が今の回のプロジェクトと違うものは、画像を開かずに対象外にする

### 3. 画像を見て当てはめる(Claudeの仕事)

残った画像だけを **Readで1回ずつ** 開き、`slots` の空き枠(見出し)と突き合わせる。

- **枠の順番に撮ってくれる前提で、先頭の空き枠から順に当てはめる。** 合わなければ後ろの枠を探す
- 同じ手順・同じ場面の取り直しは、完成に近い方だけを使う(別の場面は取り直しではない)
- **どの枠にも当てはまらない画像は、勝手に置かず先生に聞く**
- 1つの手順に画像2枚以上の時は、`slots` に枠が2つ並んでいるので、場面の順に入れる

### 4. 置く(コピーと赤枠を1コマンドで)

```bash
# 赤枠なし(ダイアログ・全体の画面)
node scripts/shot-watch.mjs place "<画像>" <courseSlug> <回数> <番号>

# 赤枠あり(コード画面で変更したブロックがある)
node scripts/shot-watch.mjs place "<画像>" <courseSlug> <回数> <番号> 636,461,527,171
```

座標は画像のピクセル(左上が0,0)。`x,y` が枠の左上、`w,h` が幅と高さ。
FireShotの画像は横1921px前後で、ブロックが大きく映っているので目で当てやすい。
赤枠のルールは lesson-writer の 5b の通り(**1枚に1回だけ**)。

同じ画像を2つの枠に使う時は、`place` を枠の数だけ動かす(赤枠の位置を変えられる)。

### 5. 取り込み済みにして、次を待つ

```bash
node scripts/shot-watch.mjs ack "<今回出てきた画像を全部>"
```

- **使わなかった画像も `ack` に入れる**(入れないと次の `wait` でまた出てくる)
- そのあと `slots` で残りを確認する。**空き枠が残っていれば 1. に戻る**(`wait` を背景で動かして待つ)
- 空き枠が無くなったら、次のように仕上げる
  1. `npm run check` を実行し、対象の回が「スクショは全部揃っています」になるか確認する
  2. lesson-writer の手順どおり `status` を `complete` にする(授業日・見本URLが埋まっていること)
  3. 使わなかった画像とその理由(重複・白・別プロジェクト・当てはまらない)を、先生に短く報告する

## 気を付けること

- **Claudeは待っている間に画像を見に行かない。** 新しく出たと分かるのは `wait` が終わった時だけ
- FireShotのフォルダにある元の画像は**消さない**(消すのは先生が決める)
- 取り込み済みの記録は `.shot-watch.json`(リポジトリ直下、gitignore済み)に入る。
  消すと、フォルダにある全部の画像がまた「新着」として出てくる
- 撮り直しで**同じ枠を上書きしたい**時は、`place` をもう一度同じ番号で動かせばよい
  (赤枠は元の画像から付け直すので二重にならない)
- 授業の資料を書く前に画像だけ先に届く時は、`slots` が読める状態(md に画像リンクがある)にしておくこと
