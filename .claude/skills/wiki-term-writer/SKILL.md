# Scratch wikiの用語ページを作る

`src/content/lessons/scratch-wiki/<NN>.md` が用語1つにつき1ファイル。
授業資料の本文から「📖 用語名」のカードでリンクされる、生徒向けの用語集。

**書き方のトーンは [docs/writing-voice.md](../../../docs/writing-voice.md) に従う。**
授業資料と同じ「先生の声」で書く。

## 手順

### 1. 本当に必要か確かめる

まず既存の用語を見る。

```bash
grep -h '^title:' src/content/lessons/scratch-wiki/*.md
```

授業の本文で**実際に使っている**言葉だけ足す。
使っていない言葉を先回りして足さない（読まれないページが増えるだけ）。

### 2. ファイルを作る

番号は既存の続き。`order` とファイル名の `NN` を合わせる。

```markdown
---
course: "scratch-wiki"
order: 14
title: "用語名"
status: complete
---

# 用語名

（1行で言い切る定義）

## 何に使うの？

（授業のどの場面で出てくるか）

## 気を付けること

（つまずきやすい点）
```

読みガナが要る言葉は `title: "初期化（しょきか）"` のように全角カッコで付ける。
本文からは `wiki:初期化` でも `wiki:初期化（しょきか）` でも引ける。

### 3. 確認する

```bash
npm run check
npm run build
```

## 書き方のルール

### 構成

1. **1行の定義から始める。** 「クローンとは、スプライトのコピーをゲームの途中で増やす仕組みのことです。」
2. **次に「何に使うの？」。** 授業で出てくる具体例で説明する
3. **最後に「気を付けること」。** 生徒が実際にハマる所を書く

### 分量

**スクロールせずに読み切れる長さ**にする。
用語ページは授業の途中で開いて、すぐ戻るためのもの。長いと読まれない。

### 表を使う

ブロックの一覧など、並列するものは表にすると一目で分かる。

```markdown
| ブロック | 何をする？ |
| :--- | :--- |
| 自分自身のクローンを作る | 新しいクローンを1体作る |
```

### 画像は無理に入れない

**用語ページは文章だけで読めるように書く。**
スクリーンショットは、あると分かりやすいものだけ後から足す
（実体が無い画像リンクを書くと「準備中」の枠が出て、かえって読みにくい）。

### 用語どうしをつなぐ

関係する用語には、本文の中からリンクを張る。

```markdown
[変数](wiki:変数)
```

**Scratch wikiのページ内では自動検出は働かない**ので、ここは手で書く。

## レッスン側からどう使われるか

レッスンの `<aside>` の説明文に用語が出てくると、
その手順の後ろに用語カードが**自動で挿入される**（`remarkAutoWikiTerms`）。

つまり**用語ページを足すだけで、既存のレッスンからも自動でリンクされる**。
レッスン側を書き換える必要はない。

- 1つのasideから足されるのは最大2件
- 同じ用語は1ページにつき1回だけ
- 手書きの `[用語](wiki:用語)` が既にある用語は、自動では足されない

そのため、**ありふれた言葉を用語にすると大量にリンクされる**ことに注意する。
「変数」「条件」のような頻出語は既にあるので、新しく足すのは
その回に固有の、説明が要る言葉にする。
