# Claude in Chrome でScratchを実際に操作してスクショを撮る手順

授業資料(`src/content/lessons/`)のスクショを、Claude in Chromeで実際にScratchプロジェクトを
操作しながら撮るときの手順。2026年9月にsuiyo-2026-7-9の#3を作った際に、試行錯誤して
たどり着いた方法。

## 大前提: なぜ素直にスクショツールを使えないか

Claude in Chromeの`computer`ツールにある`screenshot`(`save_to_disk: true`)は、
**保存先のファイルパスを呼び出し元に返さない**。拡張機能の内部(LevelDBなど)に
保存されている可能性はあるが、Claude Codeのファイルシステムからは辿れなかった
(Downloads・AppData・拡張機能のストレージ・`chrome://`系ページ、すべて調査済みで見つからず)。

なので、**画面を実際にOSレベルでキャプチャしてファイルに保存する**という迂回策を取る。

## 手順

### 1. 対象のタブを別ウィンドウに分離する

Claude in Chromeが操作しているタブは、既定では**先生が普段使っているChromeウィンドウの
バックグラウンドタブ**として動いている。この状態でOSレベルのウィンドウキャプチャをすると、
そのとき先生が実際に見ている別のタブ(無関係な画面)を誤って撮ってしまう。

**先生に、対象タブをドラッグして別ウィンドウに切り離してもらう**(タブを画面外にドラッグ、
または右クリック→「新しいウィンドウに移動」)。これで対象タブ専用のChromeウィンドウができ、
以降はそのウィンドウだけを安全にキャプチャできる。

### 2. ウィンドウを大きくする

分離直後のウィンドウは小さいことが多く、そのままだとスクショの文字が小さく、
過去の資料と比べて見劣りする。`scripts/capture-scratch-screenshot.ps1`を使う前に、
PowerShellでウィンドウをリサイズしておく。

```powershell
Add-Type @"
using System;
using System.Runtime.InteropServices;
public class Win32Resize {
    [DllImport("user32.dll")] public static extern bool SetWindowPos(IntPtr hWnd, IntPtr hWndInsertAfter, int X, int Y, int cx, int cy, uint uFlags);
}
"@
$proc = Get-Process -Name chrome | Where-Object { $_.MainWindowTitle -like "*Scratch*" } | Select-Object -First 1
[Win32Resize]::SetWindowPos($proc.MainWindowHandle, [IntPtr]::Zero, 20, 20, 1900, 1120, 0x0040) | Out-Null
```

目安は幅1900px前後。過去の資料は1920px相当のウィンドウで撮られている。

### 3. Claude in Chromeで操作する

いつも通り`mcp__claude-in-chrome__computer`でクリック・ドラッグして授業の手順を進める。
このときの注意点は下の「ブロックのドラッグでハマったこと」を参照。

### 4. スクショを撮る

```bash
powershell -ExecutionPolicy Bypass -File "scripts/capture-scratch-screenshot.ps1" -OutPath "public/lessons/<course>/<NN>/image-N.png"
```

このスクリプトは:
- Scratchのウィンドウをフォアグラウンドに持ってくる(確認できないと中止する — 無関係な画面を誤って撮らないため)
- ウィンドウ全体をキャプチャしたあと、上端211px・下端15pxを切り落として、
  タブ・URLバー・ブックマークバー・デバッグ中バナーなどブラウザ側のUIを除去する
  (この数値はウィンドウの「中身」の高さが変わっても、ブラウザのUI自体の高さは
  変わらないので基本そのまま使い回せる)

### 5. 撮ったスクショを確認する

**保存する前に必ずReadツールで開いて確認する。** 特に:

- マウスカーソルがブロックの上に乗っていないか(乗っていたら少し動かしてから撮り直す)
- **ドラッグしたブロックが本当に接続されているか**(浮いたまま保存してしまうミスが起きやすい。
  「定義」ブロックから最後のブロックまで、隙間なく繋がっているか拡大して確認する)
- 意図した手順の状態になっているか(1つ前の手順の状態のまま撮ってしまっていないか)

## ブロックのドラッグでハマったこと

Scratchのブロックパレットは、ちょっとしたドラッグの失敗で**パレット自体がスクロールしてしまう**
(ブロックを掴み損ねると、ドラッグ操作がパレットのスクロールジェスチャーとして扱われる)。
これにより「さっき見えていた位置に別のブロックが来ている」状態になり、狙ったブロックと
違うブロックをドラッグしてしまうミスが多発した。

対策:
- **ドラッグの直前に必ずスクリーンショットを撮って、そのときの正確な座標を使う。**
  1つ前のスクリーンショットの座標を使い回さない(1px単位でパレットがずれていることがある)
- ブロックを掴むときは、ブロックの**文字が書かれている部分**(入力欄や矢印アイコンではない場所)
  を狙う
- ドラッグ後は必ずスクリーンショット(または`zoom`)で結果を確認する。特に:
  - 意図したブロックが接続されたか
  - **意図しない場所(if文の中など)に丸ごと入ってしまっていないか**
    (これをやると、それより下に繋がっていた全部のブロックが一緒に飲み込まれる)
- 想定と違う結果になったら、その場で直そうとせず**Ctrl+Zで一旦戻してからやり直す**方が早い
- パレット内を下にスクロールしたいときは、スクロールホイールの`scroll`アクションが
  効かないことがある。その場合はパレット右端の**スクロールバーを直接ドラッグ**する
  (ただし勢いよくドラッグすると別カテゴリまで飛んでしまうので、小刻みに動かす)

## マウスカーソルが写り込む問題

OSレベルでキャプチャすると、Claude in Chromeが自動操作で使っているマウスカーソルが
写り込むことがある。**カーソルを画面外に動かすだけでは直らない**(Claude in Chromeが
裏でカーソル位置を保持し続けていて、動かしてもキャプチャの直前に元へ戻ってしまう)。

`capture-scratch-screenshot.ps1`では、位置をずらす代わりに`ShowCursor(false)`で
**キャプチャの瞬間だけカーソルの表示自体を消す**方法で対応している
(キャプチャ後は必ず`ShowCursor(true)`で戻す)。

それでも、**キャプチャ直前に「カーソルをどかすための」クリックを追加すると、
そのクリック自体がカーソルを再表示させてしまい逆効果になる**ことが分かった。
作業(ドラッグ等)が終わったら余計なクリックを挟まず、そのままキャプチャするのが安全。

## 話題のブロックを画面中央に置く

ブロックが作られた場所(だいたい画面左上寄り)のまま撮ると、過去の資料に比べて
見づらい。撮る前に、**キャンバスの空いている場所をドラッグしてスクリプトを
中央付近まで動かしてから**キャプチャする。

## このやり方の限界

- 対象タブを毎回別ウィンドウに分離しておく必要がある(先生の一手間)
- ウィンドウを画面上に表示させたままキャプチャするので、キャプチャの瞬間に
  他のウィンドウ(通知など)がその領域に重なると写り込むリスクがゼロではない。
  怪しいと思ったら撮り直す
