# 授業資料の記法ルール

このサイトが読み込む `src/content/courses/` と `src/content/lessons/` の中身をどう書くか、
というルールをまとめたもの。Notionから移行した過去の資料も、これから新しく書く資料も、
このルールに合わせる。

実際に移行済みの9コース分のファイルを見て書いているので、ここに書いてあるパターンは
全部 `src/content/lessons/` の中に実例がある。迷ったら実例を探すのが一番早い。

## ディレクトリ構成

```text
src/content/
├── courses/
│   └── <courseSlug>.md       # コース1つにつき1ファイル(例: kinyo-2026-1-3.md)
└── lessons/
    └── <courseSlug>/
        └── <NN>.md           # 授業回1つにつき1ファイル。NNは "00", "01"... の2桁ゼロ埋め
public/
└── lessons/
    └── <courseSlug>/
        └── <NN>/
            └── imageX.png     # そのレッスンで使う画像
_notion-source/                # Notionエクスポートの生データ置き場(.gitignore済み、コミットしない)
scripts/
├── migrate-from-notion.mjs    # _notion-source/ → src/content/ + public/lessons/ への変換スクリプト
├── new-lesson.mjs             # 新しい回の雛形を作る (npm run new-lesson)
├── import-shots.mjs           # 撮ったスクショを命名規則に並べ替える (npm run shots)
└── check-lessons.mjs          # 記法・スクショ・用語リンクの検査 (npm run check)
docs/
├── content-notation.md        # このファイル(記法のルール)
└── writing-voice.md           # 本文の言い回し(トーン)
.claude/
└── skills/
    ├── lesson-writer/         # 授業回を書く時のClaude Code用スキル
    └── wiki-term-writer/      # 用語ページを書く時のスキル
```

## よく使うコマンド

```bash
npm run new-lesson -- kinyo-2026-7-9 4 "タイトルとリザルトを作ろう"   # 雛形を作る
npm run check                                                        # 記法を検査する
npm run dev                                                          # 書きながら確認(制作中の回も出る)
npm run release                                                      # 生徒が見る画面を確認(制作中は出ない)
npm run shots -- kinyo-2026-7-9 3                                    # 撮ったスクショを命名規則に並べ替える
```

本文の言い回し(トーン)は [writing-voice.md](writing-voice.md) にまとめてある。

Windowsでは `dev.bat` / `release.bat` をダブルクリックしても同じことができる。

| | 見えるもの | ポート |
| :--- | :--- | :--- |
| `dev.bat` | 制作中(draft)の回も「制作中」バッジ付きで出る | 4321 |
| `release.bat` | 本番と同じビルド。制作中の回は出ない | 4322 |

ポートを分けてあるので、**両方同時に立ち上げて見比べられる**。

`npm run check` は次を見ている。**エラーが0になってからコミットする。**

- frontmatterの不足、`order`とファイル名の食い違い、存在しないコース
- `wiki:` の用語がScratch wikiのページに解決できない
- `status: complete` なのにスクショが足りない(逆に全部揃っていれば `complete` にできると教えてくれる)
- 「やってみよう」の中の `###` 手順にスクショやasideが無い

`courseSlug` は既存のものは `<曜日ローマ字>-<年>-<開始月>-<終了月>` の形式に揃えている
(例: `kinyo-2026-1-3` = 金曜日, 2026年1〜3月期)。曜日を含まないコース(体験授業・Scratch wiki)は
`taiken-jugyo` / `scratch-wiki` のように内容が分かる短い英字にする。

## コースのfrontmatter (`src/content/courses/<slug>.md`)

```yaml
---
title: "金曜ゲーム"        # コース名(曜日・期間を含まない)
period: "2026 1~3月"       # 表示用の期間
dayOfWeek: "金曜日"        # 該当しない場合は "-" や "単発" など
order: 20                  # トップページでの並び順(大きいほど上に表示される)
status: complete           # "complete" | "partial" | "draft"
note: "..."                # 任意。トップ/コース一覧ページの💡欄に表示される
---
```

本文は基本的に空でよい(トップページ・コース一覧ページはfrontmatterしか見ていない)。

### `order` の付け方(実際に使っている値)

`order` は日付順を厳密に守る必要はなく、「大きい数字ほど上に表示したい」という表示順の指定でしかない。
今使っている値:

| コース | order |
| :--- | :--- |
| Scratch wiki(リファレンス) | 1 |
| シューティングゲーム(2025 10~12月) | 5 |
| ブロック崩しゲーム(2025 10~12月) | 6 |
| 金曜ゲーム(2026 1~3月) | 20 |
| 火曜ゲーム(2026 1~3月) | 21 |
| 金曜ゲーム(2026 4~6月) | 22 |
| 金曜ゲーム(2026 7~9月) | 23 |
| 水曜日ゲーム(2026 7~9月) | 24 |
| 体験授業(単発・随時) | 30 |

新しいコースを追加する時は、時系列で一番新しいものが一番大きい数字になるように、
間を空けて(例: 25, 26...)採番する。体験授業のような単発コースは常に一番上(一番大きい数字)に
しておくと見つけやすい。

### トップページの並び(`src/pages/index.astro`)

トップページはコースを`period`ごとに列(カラム)分けして表示し、新しい期間が左に来るように
`order`の最大値で列を並べ替えている。`taiken-jugyo`と`scratch-wiki`だけは`period`を持たない
特別枠なので、`OTHER_SLUGS`というハードコードされたslugのSetで除外し、
一番下に区切り線付きの「その他」として表示している(`src/pages/index.astro`内)。
新しく期間に属さないコース(単発講座やリファレンス集など)を増やす場合は、
このSetにslugを追加する。

### `hubLesson`: ハブ形式のコース(体験授業など)

体験授業のように、講師がリアルタイムで画面を操作しながら進行する回では、
「目次になるハブページ」から各トピックのページへ飛び、話し終わったら戻ってくる、
という導線が必要になる。これを`hubLesson`フィールドで実現している。

```yaml
---
title: "体験授業"
period: "体験授業"
dayOfWeek: "単発"
order: 30
status: complete
hubLesson: "00"   # このコースの中で「ハブ」として扱うレッスンのorder(2桁ゼロ埋め文字列)
---
```

`hubLesson`を指定すると:

- **ハブレッスンの本文は、コース一覧ページのURL(`/courses/<slug>/`)自体で表示される。**
  独立した`/courses/<slug>/<hubLesson>/`ページは作られない
  (`src/pages/courses/[course]/index.astro`が、`hubLesson`のレッスンを`getEntry`で取得して
  そのまま`<Content />`として描画し、通常のレッスン一覧UIの代わりに表示する)。
  `src/pages/courses/[course]/[lesson].astro`の`getStaticPaths`側では、
  ハブレッスンの分だけルート生成から除外している(二重にページができないようにするため)。
- ハブページ以外の各レッスンページの本文の下に、大きなボタン風の「戻る」リンクが
  追加される(`.hub-return-button`。スクロールして読み終えた後、上まで戻らず
  すぐ次のページに移れるようにするため)。リンク先は`/courses/<slug>/`
  (=ハブページ)。
- ページ上部の「戻る」リンクは、ハブの有無に関わらずどのコースでも
  常に`/courses/<slug>/`を指す(ハブがあるコースではこれがそのままハブページに戻ることになる)。

ハブページの本文中で、他のレッスンへのリンクは
`[Scratch紹介](/courses/taiken-jugyo/01/)`のように直接サイト内パスで書く
(Notionから取り込む場合は、`scripts/migrate-from-notion.mjs`が自動的に変換する。
次の「Notionから取り込む」節を参照)。このリンクは独立した段落に置くと、
`Layout.astro`のCSSが自動的に「▶ このページを開く」という大きめのボタンに整形する
(Scratch wikiの用語ページへのリンクだけは、文中に埋め込む小さいピル型チップになる。
`href`が`/courses/scratch-wiki/`かどうかで判定を分けている)。

## レッスンのfrontmatter (`src/content/lessons/<courseSlug>/<NN>.md`)

```yaml
---
course: "kinyo-2026-1-3"   # 対応するコースのslug
order: 3                   # "#3" などの回数。ファイル名のNN(2桁ゼロ埋め)と対応させる
title: "#3 敵を作ろう"      # 一覧・ページタイトルに表示される
status: complete           # "complete" | "partial" | "draft"
note: "..."                # 任意。status: partial の時にページ上部の💡欄に表示される
---
```

`sessionDate` のようなフィールドは今のところ使っていない。授業日の情報は本文中に
`授業日: 2026年2月6日` のようにテキストとしてそのまま書かれている(次の節を参照)。
将来的にfrontmatterに切り出したくなったら `src/content/config.ts` のschemaに追加すること。

### `status` の3つの値

コース・レッスンのどちらにも使える。

| 値 | 公開サイト | プレビュー(npm run dev) | 使う場面 |
| :--- | :--- | :--- | :--- |
| `complete` | 出る | 出る | 仕上がっている |
| `partial` | 出る(「画像準備中」バッジ付き) | 同じ | 読めるが画像などが揃っていない |
| `draft` | **出ない** | 出る(「制作中」バッジ付き) | 制作中。生徒に見せたくない |

### `status: draft`(制作中)

**書きかけの回を生徒に見せないためのもの。**

`draft` を付けた回は、公開サイト(`npm run build`)ではページ自体が作られず、
コース一覧にも、トップページの回数にも出てこない。

一方 `npm run dev` のプレビューでは表示される。
先生が授業前に下書きを読み返したり、書きながら見た目を確かめたりできるようにするため。
プレビューでは一覧に「制作中」バッジが付き、ページの上にも
「このページは制作中です。公開サイトには出ていません」という注意書きが出る。

授業でスクショを撮って貼り、授業日と見本プロジェクトのURLを埋めたら
`complete`(または画像がまだなら `partial`)に変えて公開する。

判定は `src/utils/visibility.ts` の `isPublished()` にまとまっていて、
トップページ・コース一覧・レッスンページの3か所で使っている。

### `status: partial` の使いどころ

コース・レッスンのどちらにも `status: partial` が使える。

- コースに付けると、トップページのカードに「一部準備中」バッジが付く。
- レッスンに付けると、コース一覧ページのそのレッスン名の横に「画像準備中」バッジが付き、
  レッスンページの本文の上に `note` の内容が💡ボックスで表示される。
- レッスンが1件もないコースは、コース一覧ページに
  「まだ授業回のページがありません。準備が整い次第、追加します。」と自動で表示される
  (`src/pages/courses/[course]/index.astro` の分岐処理)。

過去にNotionから移行した回はすべて `status: complete`。
2026年8月に書き足した金曜/水曜の新しい回と、Scratch wikiの追加用語は、
スクショがまだ無いので `draft` / `partial` になっている。

## 本文の記法

本文はNotionのMarkdownエクスポートの書き方をほぼそのまま使う。

### 見出しレベル(2つの流儀が混在している)

コースが作られた時期によって、見出しの深さの使い方が2パターンある。**どちらも正しく表示されるので
無理に統一しない**。新しく書く時はどちらでもよいが、1つのレッスンの中では一貫させること。

- **新しい形式**(2026年7月〜の金曜/水曜ゲームなど): `#` はページタイトルのみ、
  `## 大セクション`、`### 手順の小見出し` という3段階。
- **古い形式**(2025〜2026年前半の金曜/火曜/シューティング/ブロック崩しなど): `#` を
  ページタイトルと大セクションの両方に使い(同じ階層)、`## 手順の小見出し` で1段だけ下げる、
  という2段階。

どちらの形式でも、`src/layouts/Layout.astro` のグローバルCSSが `h1`/`h2`/`h3` それぞれに
見た目を付けているので表示上の問題はない。

### よく出てくるセクション名(呼び方が時期によって揺れている)

新しく書く時は左の「推奨」を使うとよいが、右側の旧名称が出てきても、それは過去の資料の
書き方なので**リネームして回る必要はない**。

| 役割 | 推奨(新しいレッスンで使う) | 資料内で実際に使われている旧名称 |
| :--- | :--- | :--- |
| その回のゴール(箇条書き) | `目標` | (これは全時期共通) |
| 先生の完成品Scratchプロジェクトへのリンク | `見本` | `プロジェクト` |
| 事前に知っておくと良い知識・用語の解説(任意) | `覚えること` | `覚える事` |
| メインの制作パート | `やってみよう` | (古い形式では大セクション名がそのまま制作内容、例: `敵を作ろう`) |
| 締めの一言 | `終わり` | `終了`、`終了！！` |
| 追加でやってみる課題(任意) | `エクストラ課題` | `追加の実装` |
| その日の振り返りフォーム(任意、2026年7月〜の新しい回のみ) | `今日のひとことを書こう！`(Google Formの`forms.gle`リンク) | (旧形式にはなし) |

`見本`/`プロジェクト`セクションと`今日のひとことを書こう！`セクションは、
**URLをそのままの行に書くだけでよい**(GitHub Flavored Markdownの自動リンクが効く)。

リンクの文字は `astro.config.mjs` の `remarkFriendlyLinkText` が自動で置き換えるので、
本文に長いURLがそのまま出ることはない。

| URL | 表示される文字 | 右側のラベル |
| :--- | :--- | :--- |
| `scratch.mit.edu/projects/...` | 先生の見本プロジェクト | Scratchで開く → |
| `forms.gle/...` / `docs.google.com/forms/...` | 今日のひとことフォーム | 回答する → |

自分で `[好きな文字](url)` と書いた場合はその文字が尊重されるので、
別の見せ方をしたい時は手で書けばよい。

先生のScratchプロジェクトURLがまだ無い時は、
`（先生のプロジェクトURLを入れる）` とプレーンテキストで書いて残しておく。

`覚えること`セクションは任意で、算数・理科などプログラミング以外の前提知識を、図解や
参考動画・参考サイトへのリンクと一緒に説明する時に使う(例: `block-kuzushi-2025-10-12/01.md` の
「角度の考え方」)。

### 画像

```markdown
![image.png](/lessons/kinyo-2026-1-3/03/image.png)
```

- パスは必ず **`/lessons/<courseSlug>/<NN>/ファイル名`** というサイトルート相対パスにする。
  GitHub Pagesのbase path(`/Vantan-JuniorHighSchool-Programming`)は
  `astro.config.mjs` のremarkプラグインがビルド時に自動で付け足すので、**自分で書かない**。
- ファイル名の半角スペースはハイフンに置き換える(例: `image 1.png` → `image-1.png`)。
  これはURLにスペースが入る事故を防ぐため。
- 画像の実体は `public/lessons/<courseSlug>/<NN>/` に置く。
- **他のコース/レッスンの画像を再利用することもできる**(例: `scratch-wiki`の解説ページが
  `suiyo-2026-7-9`のレッスンのスクリーンショットを流用している)。その場合は
  `public/lessons/<借りる側のcourseSlug>/<NN>/` に画像をコピーしてから参照する
  (`migrate-from-notion.mjs`は元のNotionの相対パス `../他のフォルダ/画像.png` を自動で
  解決してコピーしてくれる。詳しくはスクリプト内の`relativeResolved`の処理を参照)。

### スクショが後から用意される場合(先に本文だけ書く時)

授業資料は「先に本文を書く → 授業でScratchを作りながらスクショを撮る → 後から貼る」
という順番で作ることが多い。そのため、**実体がまだ無くても画像リンクを先に書いてよい**。

`astro.config.mjs` の `remarkMissingImagePlaceholder` が、ビルド時に
`public/` に実体があるかを調べて、無ければ「📸 スクリーンショット準備中」の
点線の枠に差し替える。壊れた画像アイコンにはならない。

```markdown
![image.png](/lessons/kinyo-2026-7-9/03/image.png)   ← 実体が無い間はプレースホルダー表示
```

あとから `public/lessons/kinyo-2026-7-9/03/image.png` を置けば、
**次のビルドから自動的にその画像が表示される**(Markdownは書き換えなくてよい)。

この状態の間はレッスンの`status`を`partial`にして、
`note: "スクリーンショットは授業のあとに追加します。"` を付けておく。
スクショが全部揃ったら`complete`に戻す(`npm run check`が教えてくれる)。

### コールアウト(吹き出し)

```markdown
<aside>
💡

説明文1行目。

説明文2行目(段落を分けたい時は空行を入れる)。

</aside>
```

- 1行目は絵文字(基本は💡)。2行目以降が本文。
- `Layout.astro` のグローバルCSSが `aside` タグを自動でカード風にスタイリングするので、
  クラス名などは付けなくてよい。
- **書く内容のトーン**(中学生向けであることを踏まえて):
  - です・ます調で、生徒に語りかけるように書く(「〜しましょう」「〜ですね」)。
  - 新しく作る変数名・ブロック名は、英単語の意味を添えて説明する
    (例: 「名前は"MoveSpeed"にします。意味はそのまま「移動のスピード」ですね。」)。
  - 「なぜこの操作が必要か」を先に一言添えてから、具体的な手順の説明に入る。
  - 「こうすると〜になります」という因果関係の説明を使うと分かりやすい。
  - 詳しい手順は aside の外に番号付きリスト(`1.` `2.` ...)として書く。asideの中に手順を
    書かない(asideは「なぜ・何をするか」の説明、外の番号リストが「具体的な操作」という役割分担)。

### リストの使い分け

- `目標`セクションや、対頂角・同位角・錯角のような単なる列挙 → `- ` の箇条書き
- 実際にScratchで操作する手順 → `1.` `2.` の番号付きリスト(常にaside/画像の直後に置く)

### Scratch wikiの用語リンク

新しい用語が初めて出てくる手順の**すぐ後ろ**に、1行だけの段落として置く。

```markdown
[クローン](wiki:クローン)
```

- **`wiki:用語名` と書く。ページ番号(`/courses/scratch-wiki/09/`)は書かない。**
  用語を1つ足して番号がずれた時に全レッスンを直す羽目になるため、
  番号を引くのは `astro.config.mjs` の `remarkResolveWikiTerms` がビルド時にやる
- 読みガナ付きのタイトルは括弧を含めても外しても引ける
  (`wiki:初期化（しょきか）` でも `wiki:初期化` でもよい)
- 解決できない用語は**ビルド時に警告**が出て、`npm run check` はエラーにする
- **「クローンとは：」のような前置きは書かない。** 旧Notion資料はこの書き方だったが、
  現在は用語カードとして表示されるので前置きは不要

表示は2通りに自動で切り替わる(`Layout.astro`)。

| 置き方 | 見た目 |
| :--- | :--- |
| 1行だけの段落として置く | 📖バッジ + 用語名 + 「用語をおさらい →」の**用語カード** |
| 文章の途中に埋め込む | 「📖 用語名」の小さいピル型チップ |

**用語ページが足りない時は先にwikiに追加する。**
`src/content/lessons/scratch-wiki/<NN>.md` に番号の続きで作れば、すぐ `wiki:` で引けるようになる。

Scratch wiki以外の内部ページへのリンク(他コースの別レッスンへのリンクなど)は、このサイトでは
解決できないため、リンクを書かずプレーンテキストにしておく。

(画像は前述の通り他コースのものも参照できる。)

## 画像が見つからない場合の表記

Notionのエクスポートに画像の実体が含まれていなかった場合は、壊れた画像リンクにする代わりに
次の形式のテキストを入れる(`scripts/migrate-from-notion.mjs` が自動でこの形にする):

```markdown
*[画像が見つかりません: image 2.png（元のNotionエクスポートに含まれていませんでした）]*
```

## 新しいレッスンをゼロから書く場合(Notion経由でない場合)

**まず `npm run new-lesson` で雛形を作るのが早い。**

```bash
npm run new-lesson -- <courseSlug> <回数> "<タイトル>" [手順の数]
```

## Notionから新しいコース/レッスンを取り込む・更新する手順

1. Notionで対象のページを開き、「•••」→ エクスポート → Markdown & CSV
   → **「サブページを含む」に必ずチェックを入れて**書き出す
   (チェックを忘れると画像やレッスン本文が抜け落ちる)。
2. 展開したフォルダを `_notion-source/` 以下に置く。
   **フォルダの階層はNotionのエクスポートごとに微妙に変わることがある**
   (`プライベート、シェア/バンタン中等部/...` の場合と
   `プライベート、シェア/バンタン/バンタン中等部/...` の場合があった)。
   決め打ちで「中身がない」と判断せず、`_notion-source/` の下を実際にたどって
   本当のフォルダ名・階層を確認してから次に進むこと(過去に階層を1段見誤って、
   実在するコースを「未移行」と誤判定したことがある)。
3. `scripts/migrate-from-notion.mjs` の `COURSES` 配列に、対象コースの
   `srcFolder`(`_notion-source/`直下でのフォルダ名) ・ `slug` ・ `title` ・
   `dayOfWeek` ・ `period` ・ `order` を追加する。
4. `node scripts/migrate-from-notion.mjs` を実行する。
   コンソールに `画像が見つかりません` という警告が出たら、Notion側の元データに
   その画像が含まれていなかったということなので、無視してよい
   (本文には自動でプレースホルダーが入る)。
5. `npm run dev` でプレビューして、レッスン一覧・画像・コールアウトの表示を確認する。

このスクリプトは `#N タイトル.md` という命名のファイルが並ぶ、通常の週替わりレッスン形式の
コースにしか自動対応していない。体験授業やScratch wikiのように「#N」形式ではない
特殊な構成のコースを追加する場合は、スクリプト冒頭の `TAIKEN_LESSONS` ・
`SCRATCH_WIKI_LESSONS` のように、ファイル名と表示順を手で対応付ける配列を追記し、
スクリプト末尾の該当セクションでその配列を使って処理する。

これらの配列は、本文中の自分自身のコースへの内部リンク(例: 体験授業のハブページから
他のトピックページへのリンク)を実際のサイト内リンクに変換する時にも使われる
(`processLesson`内の、`decoded.includes("体験授業/")` / `decoded.includes("Scratch wiki/")`
の分岐を参照)。同じ仕組みを新しいハブ形式のコースに適用したい場合は、この分岐に
対象コース用の条件を追加する。
