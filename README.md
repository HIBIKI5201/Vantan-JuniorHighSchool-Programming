# バンタン中等部 プログラミング授業資料

中学生向けのScratch授業で使う資料を置いて、公開しているリポジトリです。
生徒はここで公開されたページを見ながら、その日のゲームを作ります。

**公開サイト:** https://hibiki5201.github.io/Vantan-JuniorHighSchool-Programming/

資料は1回の授業につき1ページ。ページの中身は「目標 → 見本 → やってみよう(手順) → 終わり」
という流れで、手順ごとにスクリーンショットと💡の説明が付きます。
そのほかに、生徒がいつでも引ける用語集(Scratch wiki)があります。

---

## はじめての人へ（セットアップ）

資料を書くのに必要なのは、次の2つだけです。

1. **[Node.js](https://nodejs.org/ja)** をインストールする(LTS版でOK)
2. **[GitHub Desktop](https://desktop.github.com/)** をインストールして、このリポジトリを
   自分のパソコンに「Clone(クローン)」する

クローンしたフォルダの中にある **`write.bat` をダブルクリック** すると、
資料を書くためのエディタがブラウザで開きます(初回だけ、準備に数分かかります)。

> Macの場合は、フォルダをターミナルで開いて `npm install` → `npm run write` を実行してください。

## 書き方の流れ

```
write.bat でエディタを開く
  → 左のリストから回を選ぶ(または「＋ 新しい回を作る」)
  → 本文を書く（保存すると .md ファイルが書き換わります）
  → dev.bat で見え方を確認する
  → GitHub Desktop で コミット → プッシュ
```

`main` ブランチにプッシュすると、GitHub Actionsが自動でビルドして公開サイトを更新します
(反映まで1〜2分)。

### 1. エディタで書く（`write.bat`）

Notionのような画面で、Markdownの記法を知らなくても書けるようにしてあります。

- 空の行で **`/`** を打つと、入れられるもの(見出し・箇条書き・手順・コールアウト・
  スクショ・用語カード)が一覧で出ます。
- **途中に足したい時は、ブロックの上にマウスを乗せると左に出る `＋`** を押します
  (そのブロックの下に足して、そのまま種類を選べます)。隣の `⠿` は種類の変更、`×` は削除です。
  文章のブロックなら、行末で Enter を押すだけでも下に足せます。
- `# ` `## ` `- ` `1. ` と打ち始めると、そのまま見出しやリストになります。
- **スクショは Ctrl+V で貼れます。** `public/lessons/…` の正しい場所に、
  `image-0.png` `image-1.png` … という決まった名前で自動的に保存されます。
- **用語カード**は、Scratch wikiにある用語を選ぶだけです。リンク先のページ番号は
  公開時に自動で解決されるので、気にしなくて大丈夫です。
- **Ctrl+Z で元に戻せます**(やり直しは Ctrl+Shift+Z。右上の `↩︎` `↪︎` でも同じ)。
  文字の入力は打ち終わったところまでが1回分、ブロックを足した・消した・種類を変えた操作は
  1回ずつ戻せます。
- 左下の「記法チェックを実行」で、書き方の間違いやスクショの不足を確認できます。
- **Ctrl+S で保存**。保存すると、リポジトリの中のファイルが直接書き換わります。

灰色の枠で「そのまま保存される部分」と出ているところは、表など、
エディタが扱っていない書き方の部分です。触らなければ元のまま残ります。

### 2. 見え方を確認する（`dev.bat` / `release.bat`）

| | 見えるもの | ポート |
| :--- | :--- | :--- |
| `write.bat` | 資料を書くエディタ | 4321 |
| `dev.bat` | 制作中(draft)の回も「制作中」バッジ付きで出る | 4321 |
| `release.bat` | 本番と同じビルド。制作中の回は出ない | 4322 |

`dev` と `release` はポートが違うので、両方同時に立ち上げて見比べられます。

### 3. コミットして公開する

GitHub Desktopで変更内容を確認して、コミットメッセージを書いてプッシュします。
**生徒に見せたくない書きかけの回は、公開の状態を `draft` にしておけば公開サイトには出ません。**

| 公開の状態 | 公開サイト | 使う場面 |
| :--- | :--- | :--- |
| `draft` | **出ない** | 制作中。まだ生徒に見せたくない |
| `partial` | 出る(「画像準備中」バッジ付き) | 読めるが、スクショが授業待ち |
| `complete` | 出る | 仕上がっている |

授業の進め方としては、**先に本文だけ書いて `draft`/`partial` にしておき、
授業でScratchを作りながらスクショを撮って、あとから貼って `complete` にする**、
という順番が多いです。スクショが無い間は「📸 スクリーンショット準備中」と表示されるので、
画像が壊れて見えることはありません。

## 複数人で書く時の約束

- **`main` に直接プッシュしない。** `dev` ブランチか、作業用のブランチで書いて、
  プルリクエストを出してください(公開サイトが更新されるのは `main` にマージした時です)。
- **1つの回は1人が書く。** 同じファイルを2人で同時に開くと、あとから保存した方で
  上書きされます。誰がどの回を書くかは事前に決めてください。
- **コミットする前に「記法チェック」を実行して、エラーを0にする。**
- **本文の言い回しは既存の資料に合わせる。** 中学生が読むものなので、です・ます調で、
  「なぜこれをするのか」を一言添えてから手順に入ります。
  → [docs/writing-voice.md](docs/writing-voice.md) に、既存の資料から抜き出してまとめてあります。
- **用語ページ(Scratch wiki)が足りない時は、先にwikiに用語を足す。**
  レッスン側から `wiki:` で引けるようになります。

## 困った時

| こんな時 | どうするか |
| :--- | :--- |
| エディタが開かない | 黒い画面(PowerShell)に出ているメッセージを確認する。`Node.js が見つかりません` なら、Node.jsのインストールから |
| 保存したのにサイトに出ない | 公開の状態が `draft` になっていないか確認する |
| スクショが「準備中」のまま | 画像をエディタで貼り直す。`public/lessons/<コース>/<回>/` に置いてあるかも確認する |
| 用語カードに「wikiに無い」と出る | その用語のページを Scratch wiki のコースに追加する |
| 間違えて消してしまった | GitHub Desktop で変更を「Discard(破棄)」すれば、最後にコミットした状態に戻ります |

### 技術的なこと

- [Astro](https://astro.build/) の静的サイト。資料は `src/content/lessons/<コース>/<NN>.md`、
  画像は `public/lessons/<コース>/<NN>/` に置いてあります。
- エディタは `editor/`(画面) と `scripts/editor-server.mjs`(保存用のAPI)。
  `npm run dev` の時だけ動き、**公開サイトのビルドには含まれません**。
- コマンドで操作したい場合:

```bash
npm install
npm run write      # エディタを開く                        :4321
npm run dev        # 書きながら確認(制作中の回も出る)       :4321
npm run release    # 生徒が見る画面を確認(制作中は出ない)   :4322
npm run check      # 記法・用語リンク・スクショの検査
npm run new-lesson -- <コース> <回数> "<タイトル>"   # 回の雛形を作る
npm run shots -- <コース> <回数>                    # 撮ったスクショを命名規則に並べ替える
npm run build      # ./dist に静的ビルド
```
